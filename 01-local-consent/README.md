# Local patient-consent checkpoint

This is the completed reference for the first feature. It uses memory and a test
identity. It does not implement real authentication or durable cloud storage.

## Run

Install the .NET 10 SDK, then work in this folder:

```text
dotnet run --project src/Consent.Demo
dotnet run --project tests/Consent.Checks
```

Expected demonstration:

```text
Forbidden: success=false
Withdrawn: success=true
AlreadyWithdrawn: success=true
Audit records: 1; pending events: 1
```

The checks finish with `12/12 checks passed`. A failing check returns a nonzero
exit code. This is an executable checks project; `dotnet test` is not its runner.

## Build your own with Kiro

Use the root starter tool to create a separate unfinished practice workspace.
Ask Kiro to create a requirements-first consent-withdrawal spec from the brief,
preserve contracts.md and the acceptance checks, and implement one task at a time.
Run `dotnet run --project tests/Consent.Checks` from that practice root.

Compare behavior and public contracts, not private implementation line numbers.
Inspect changed checks separately from changed implementation. If you need to
recover before the next lab, return to this completed checkpoint and note that
you switched paths. Do not claim the reference was generated by your session.

## What to inspect

Review the authorization branch, version comparison, repeat handling, and commit
boundary. The failure callback runs before the collections change. The lock makes
this local model consistent under the supplied concurrency check; it does not
prove distributed transaction behavior or crash durability.

No AWS resources require cleanup. Build outputs under bin/ and obj/ are ignored.
